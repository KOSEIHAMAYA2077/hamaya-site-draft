# コンテンツの追加と差し替え

本文はMarkdown、プロフィールは `src/data/site.json` で管理します。画面の表示用に架空の作品や経歴は足していません。現在、作品と記事の公開件数は0件です。

「大学入学以降の制作」「生成AIを使った制作」「AtCoderに参加したこと」など、会話で出たテーマは追加する内容の候補です。件数、期間、活動名、実績の説明を、確認前にプロフィールの事実として補ってはいません。

## 記事を作る

```sh
npm run new -- note first-note --title "今日学んだこと"
```

`src/content/notes/first-note.md` ができます。先頭の `---` に挟まれた部分が記事の設定です。

```yaml
---
title: '今日学んだこと'
description: '記事の内容を一文で書きます。'
date: '2026-10-03'
tags: ['学習']
draft: true
category: '学び'
---
```

`category` は「学び」か「雑記」です。日付は `YYYY-MM-DD` で入力します。追加スクリプトはUTCの当日を設定するので、記録したい日が異なる場合は編集してください。記事は日付の新しい順に並びます。

設定の下に本文を書きます。ページ側に記事タイトルがあるので、本文の見出しは `##` から始めます。`description` は一覧や検索に使う短い説明です。

本文にはMarkdownの記法を使います。raw HTMLはbuildで拒否するため、HTMLのコード例はバッククォートやコードブロックで囲んでください。本文のHTMLコメントは生成ページから除去しますが、元のMarkdownには残ります。コメントも非公開資料を保管する場所にはしません。

## 作品を作る

```sh
npm run new -- work first-work --title "制作の記録"
```

`src/content/works/first-work.md` ができます。共通の設定に `status` を加えます。

```yaml
---
title: '制作の記録'
description: '何をつくったかを短く書きます。'
date: '2026-10-03'
tags: []
draft: true
status: '記録'
---
```

`status` は「制作中」「完成」「記録」から選びます。公開してよい実物やリポジトリがある場合にだけ、確認済みのHTTPS URLを `url` や `repository` に追加します。ログイン情報・空白・制御文字・バックスラッシュを含むURLは使えません。未特定のURLや仮のリンクを入力する必要はありません。

本文には、何をつくったか、きっかけ、試したこと、学んだことを残せます。成果の数や本人の役割を推測して書かないでください。

### 作品の表紙を設定する

表紙は任意です。下の「画像を採用する」の手順でファイルと採用リストを用意し、作品の設定に `cover` を追加すると、作品一覧と詳細ページに表示されます。表紙がない作品は、文字だけで表示します。

```yaml
cover:
  src: 'images/work-cover.webp'
  alt: '表紙の内容を短く説明します。'
```

`src` は `public/` から見たファイルの場所です。先頭の `/` は付けず、`images/` 配下の採用済み画像を指定します。外部URL、空のフォルダ名、`.` や `..` による移動は使えません。`alt` は必須で、画像を見られない場合にも内容が伝わる短い説明を書きます。横長の16:9の画像が合わせやすいので、一覧と詳細の切り取りも確認してください。`draft: true` の作品ページは出ませんが、`public/` の画像ファイルは配布されます。

## 画像を採用する

使える追加画像はPNG・JPEG・WebP・GIF・AVIFです。拡張子は小文字の `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.avif` にします。SVGやHTMLは追加画像として受け付けません。

1. 本人が掲載可否、画像の権利、代替テキストを確認します。位置情報など不要なメタデータは、画像を保存する段階で取り除きます。
2. 採用したファイルだけを `public/images/` に置きます。ファイル名には半角英数・ハイフン・アンダースコアを使います。
3. `src/data/public-assets.json` の配列に、`public/` を含めず `images/foo.webp` の形で追加します。既存の採用項目を残し、同じパスを重複させません。
4. 本文なら `![代替テキスト](/images/foo.webp)`、表紙やプロフィールの設定なら `src: images/foo.webp` と指定します。

画像を1枚採用した場合のリスト例です。実際のファイルと同時に追加してください。

```json
["images/foo.webp"]
```

`/works/` などの内部リンクと本文の `/images/` パスには、プロジェクト用baseをbuild時に付けます。本文の画像に外部URLや `../` などの相対ファイル指定は使いません。

build前の確認では、採用リストにない `public/` ファイル、未対応形式、シンボリックリンク、存在しない採用画像を拒否します。サイト自身の固定ファイル以外を任意に置くことはできません。画像はヘッダと拡張子の対応も確認しますが、これは画像全体をデコードする検査やメタデータ除去ではありません。選んだ画像を実際に表示して確認してください。

`public/` 内の採用画像は、記事に使われていなくても、記事が `draft: true` でもコピーされます。未採用画像や非公開素材は `public/` に置きません。掲載を取りやめるときは、参照、採用リスト、画像ファイルを一緒に外します。

## 下書きと公開内容

`draft: true` のファイルは、一覧と詳細ルートのどちらからも除外します。`draft` が省略されても下書きとして扱います。`_example.md` は入力形式の見本なので、`draft: true` のまま残してください。

内容を確認して `draft: false` にすると、次のbuildから生成サイトに含まれます。この変更だけで外部公開されることはありません。GitHub Pagesへの公開作業は、本人の判断を待っています。

下書きの元ファイルもprivateリポジトリに保存されます。私的メール、非公開の業務資料、金融情報、内部メモ、認証情報は、公開・非公開にかかわらずこのサイトの内容に入れません。

## プロフィールとリンク

`src/data/site.json` の名前、説明、`bio`、`links` を編集します。未入力の値は `null` のままにしてください。AtCoderのURLが `null` の間は、押せない未入力表示になっています。

GitHubの個別作品やAtCoderは、本人のアカウントと公開してよいURLを確認してから追加します。記事の出典リンクは `[資料名](https://example.com/path)` の形で本文に書けます。外部リンクはHTTPSに限定し、ログイン情報・空白・制御文字・バックスラッシュを含めません。本文では `/notes/` や `#section` などのサイト内パスも使えます。テストの許可先を別に編集する必要はありません。HTTPS URLを実際に確認し、GitHubとAtCoderの本人リンクを推測で追加しないでください。

プロフィール画像も「画像を採用する」の手順を通します。`portrait` を `{"src": "images/portrait.webp", "alt": "本人が選んだ代替テキスト"}` にすると表示されます。縦長の枠で表示するので、選んだ画像の切り取りと代替テキストを確認してください。

## 確認してから保存する

```sh
npm run lint
npm run build
npm test
```

作品・記事・自己紹介をブラウザでも確認します。長い日本語の見出し、スマートフォンの幅、キーボード操作、リンク先、未入力の表示を見てから保存してください。プロジェクトサイト向けのbase確認手順は [README.md](../README.md) にあります。

通常buildは、現在の公開0件では5ページです。執筆道具や比較案を含める場合は `npm run build:local`（現在12ページ）、作品の比較版も含める場合は `npm run build:compare`（現在14ページ）を使います。通常buildには `/write/`・`/directions/`・`/compare/` とそれら専用のbundleを含めません。ページ数は記事・作品の掲載後に増えます。

現在の依存関係と検証範囲は [VALIDATION.md](VALIDATION.md) に記録しています。外部画像処理やSSRを追加する前に再確認してください。

## ページの題と共有表示

記事・作品の題と説明はfrontmatterを、一覧・自己紹介は各ページの短い説明を使います。OGの題・説明・種別・日本語localeも同じ値から生成します。記録の日付を実際の初回公開日とみなす設定は加えていません。

公開URLを決めたら、build時に `SITE_ORIGIN` を設定します。未設定の間はcanonicalとOGのURL・画像を生成しません。`SITE_ORIGIN` はHTTPSのoriginのみ、リポジトリのパスは `BASE_PATH` に指定します。

共有画像を本人が選んだ後、「画像を採用する」の手順で `public/images/` と `src/data/public-assets.json` に追加し、`src/data/site.json` の `socialImage` を `{"src": "images/share.webp", "alt": "画像の内容を短く説明する本人の言葉"}` に変えます。作品に表紙がある場合は、その詳細ページで表紙を共有画像として使います。画像の設定だけでは外部公開されません。未入力のままでもローカルで読めますが、外部サービスでの共有表示は公開URL・画像を決めた後に確認してください。
