# コンテンツの追加と差し替え

本文はMarkdown、プロフィールは `src/data/site.json` で管理します。画面の表示用に架空の作品や経歴は足していません。現在、作品と記事の公開件数は0件です。

## 本人の入力・採否を待っているもの

| ---------------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| 自己紹介文             | `bio: null`。画面には「自己紹介文は未入力です。」と表示 | 本人の短い文章で置き換える。未確認の職歴や成果を加えない |
| 写真・プロフィール画像 | `portrait: null`                                        | 掲載してよい写真と代替テキストを本人が選ぶ               |

| 記事・雑記             | 公開0件。旧記事の移植候補1件と見本                      | 原文の採否を確認し、本人の文章を追加する                 |

「大学入学以降の制作」「生成AIを使った制作」「AtCoderに参加したこと」など、会話で出たテーマは追加する内容の候補です。件数、期間、活動名、実績の説明を、確認前にプロフィールの事実として補ってはいません。

## 記事を作る

```sh
npm run new -- note first-note --title "今日学んだこと"
```

`src/content/notes/first-note.md` ができます。先頭の `---` に挟まれた部分が記事の設定です。

```yaml
---
title: '今日学んだこと'
description: '記事の内容を一文で書きます。'
date: '2026-10-03'
tags: ['学習']
draft: true
category: '学び'
---
```

`category` は「学び」か「雑記」です。日付は `YYYY-MM-DD` で入力します。追加スクリプトはUTCの当日を設定するので、記録したい日が異なる場合は編集してください。記事は日付の新しい順に並びます。

設定の下に本文を書きます。ページ側に記事タイトルがあるので、本文の見出しは `##` から始めます。`description` は一覧や検索に使う短い説明です。

## 作品を作る

```sh
npm run new -- work first-work --title "制作の記録"
```

`src/content/works/first-work.md` ができます。共通の設定に `status` を加えます。

```yaml
---
title: '制作の記録'
description: '何をつくったかを短く書きます。'
date: '2026-10-03'
tags: []
draft: true
status: '記録'
---
```

`status` は「制作中」「完成」「記録」から選びます。公開してよい実物やリポジトリがある場合にだけ、確認済みのHTTPS URLを `url` や `repository` に追加します。未特定のURLや仮のリンクを入力する必要はありません。

本文には、何をつくったか、きっかけ、試したこと、学んだことを残せます。成果の数や本人の役割を推測して書かないでください。

### 作品の表紙を設定する

表紙は任意です。掲載してよい画像を `public/images/` に置き、作品の設定に `cover` を追加すると、作品一覧と詳細ページに表示されます。表紙がない作品は、文字だけで表示します。

```yaml
cover:
  src: 'images/work-cover.webp'
  alt: '表紙の内容を短く説明します。'
```

`src` は `public/` から見たファイルの場所です。先頭の `/` は付けず、`images/` 配下のローカルファイルを指定します。外部URL、空のフォルダ名、`.` や `..` による移動は使えません。`alt` は必須で、画像を見られない場合にも内容が伝わる短い説明を書きます。横長の16:9の画像が合わせやすいので、一覧と詳細の切り取りも確認してください。表紙だけを設定しても、`draft: true` の作品はサイトに出ません。

## 下書きと公開内容

`draft: true` のファイルは、一覧と詳細ルートのどちらからも除外します。`draft` が省略されても下書きとして扱います。`_example.md` は入力形式の見本なので、`draft: true` のまま残してください。

内容を確認して `draft: false` にすると、次のbuildから生成サイトに含まれます。この変更だけで外部公開されることはありません。GitHub Pagesへの公開作業は、本人の判断を待っています。

下書きの元ファイルもprivateリポジトリに保存されます。私的メール、非公開の業務資料、金融情報、内部メモ、認証情報は、公開・非公開にかかわらずこのサイトの内容に入れません。

## プロフィールとリンク

`src/data/site.json` の名前、説明、`bio`、`links` を編集します。未入力の値は `null` のままにしてください。AtCoderのURLが `null` の間は、押せない未入力表示になっています。

GitHubの個別作品やAtCoderは、本人のアカウントと公開してよいURLを確認してから追加します。記事の出典リンクは `[資料名](https://example.com/path)` の形で本文に書けます。テストの許可先を別に編集する必要はありません。HTTPS URLを実際に確認し、GitHubとAtCoderの本人リンクを推測で追加しないでください。

画像は外部のURLから読み込まず、掲載可否を確認したファイルを `public/images/` に置きます。本文では `![代替テキスト](/images/filename.webp)` と書けます。`/works/` などの内部リンクと画像は、プロジェクト用baseをbuild時に自動で付けます。ファイル名には半角英数とハイフンを使い、位置情報など不要なメタデータを含めない形で保存してください。プロフィール画像は `portrait` を `{"src": "images/portrait.webp", "alt": "本人が選んだ代替テキスト"}` にすると表示されます。縦長の枠で表示するので、選んだ画像の切り取りと代替テキストを確認してください。

## 確認してから保存する

```sh
npm run lint
npm run build
npm test
```

作品・記事・自己紹介をブラウザでも確認します。長い日本語の見出し、スマートフォンの幅、キーボード操作、リンク先、未入力の表示を見てから保存してください。プロジェクトサイト向けのbase確認手順は [README.md](../README.md) にあります。

現在の依存関係と検証範囲は [VALIDATION.md](VALIDATION.md) に記録しています。外部画像処理やSSRを追加する前に再確認してください。

## ページの題と共有表示

記事・作品の題と説明はfrontmatterを、一覧・自己紹介は各ページの短い説明を使います。OGの題・説明・種別・日本語localeも同じ値から生成します。記録の日付を実際の初回公開日とみなす設定は加えていません。

公開URLを決めたら、build時に `SITE_ORIGIN` を設定します。未設定の間はcanonicalとOGのURL・画像を生成しません。`SITE_ORIGIN` はHTTPSのoriginのみ、リポジトリのパスは `BASE_PATH` に指定します。

共有画像を本人が選んだ後、`public/images/` に置き、`src/data/site.json` の `socialImage` を `{"src": "images/share.webp", "alt": "画像の内容を短く説明する本人の言葉"}` に変えます。作品に表紙がある場合は、その詳細ページで表紙を共有画像として使います。画像の設定だけでは外部公開されません。未入力のままでもローカルで読めますが、外部サービスでの共有表示は公開URL・画像を決めた後に確認してください。
