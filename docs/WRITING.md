# ブラウザで下書きを書く

ローカルサイトの `/write/` に、記事・作品の下書きをMarkdownで書き出す道具があります。主なページのナビには出していません。コマンドで作る方法と、どちらを使っても構いません。

1. `npm run dev` を起動し、`http://127.0.0.1:4321/write/` を開きます。記事か作品を選び、題・短い要約・日付・ファイル名・種類または状態を入力します。
2. 本文をMarkdownで書きます。タグは任意で、カンマか改行で区切れます。作品のURLやリポジトリは、掲載してよいHTTPSのURLが確認できた場合だけ入力します。
3. 「Markdownを確認」で内容を見て、「下書きをダウンロード」を押します。記事は `src/content/notes/`、作品は `src/content/works/` に、ダウンロードした `.md` を追加します。

ファイル名は半角の小文字・数字・ハイフンで、最大64文字です。先頭・末尾や連続するハイフン、拡張子、フォルダの指定は使いません。ブラウザが同名のダウンロードに番号を付けた場合も、そのまま既存ファイルに重ねず、別のファイル名をこの画面で指定して書き出してください。ファイルを移すときも、同じ名前の既存ファイルを上書きしないよう確認します。

入力は画面内だけで扱い、サーバー送信・自動保存・ブラウザ内への保存は行いません。画面を閉じたり再読み込みしたりすると入力を失うことがあるため、区切りでダウンロードしてください。最初の日付はUTCの当日です。記録したい日が違う場合は変更できます。

すべての書き出しは `draft: true` です。一覧と詳細ページには出ません。本人が内容と公開範囲を確認してから、Markdownの設定を `draft: false` に変えます。これは下書きを追加する道具で、GitHubへの保存や外部公開は行いません。

私的メール、非公開の業務資料、金融情報、内部メモ、認証情報は、入力・ダウンロード・リポジトリのいずれにも入れないでください。画像は掲載可否を確認したファイルを `public/images/` に置き、外部画像URLは使いません。画像、リンク、公開判断の手順は [CONTENT.md](CONTENT.md) にあります。

追加後は `npm run lint`、`npm run build`、`npm test` を実行します。将来公開する本文は、Markdownに書いたHTMLやリンクも含めて本人が確認してください。この道具の確認欄は文字列を表示するだけで、HTMLを実行しません。

GitHub Pagesのプロジェクト用baseを設定したプレビューでは、`http://127.0.0.1:4321/repo-name/write/` のようにbaseを付けます。起動・baseの設定方法は [README.md](../README.md) を参照してください。
