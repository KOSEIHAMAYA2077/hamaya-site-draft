# ブラウザで下書きを書く

ローカルサイトの `/write/` に、記事・作品をMarkdownで持ち帰る道具があります。ローカル表示の「書く」からも開けます。コマンドで作る方法と、どちらを使っても構いません。

`npm run dev` では執筆画面と `/directions/` を使えます。静的出力で使う場合は `npm run build:local` の後に `npm run preview` を実行します。`npm run build` の通常出力には `/write/`・`/directions/`・`/compare/` とそれら専用のbundleがないため、執筆画面は開けません。作品を使った比較版は `LOCAL_COMPARISON=1 npm run dev` または `npm run build:compare` で確認します。現在の公開0件では通常5ページ、ローカル用12ページ、比較用14ページです。

1. `npm run dev` を起動し、`http://127.0.0.1:4321/write/` を開きます。最初に題と本文を書きます。`?kind=work` で開くと作品、通常は記事から始まります。
2. 「読む」で本文の見え方を確認し、「書く」で編集に戻ります。「書き出しの設定」を開き、記事か作品・短い要約・日付・ファイル名・種類または状態を入力します。題・本文・要約などの必須項目が空なら書き出せません。本文や要約を自動生成する機能はありません。
3. 「書き出しを確認」でファイル名・追加先・Markdownと設定を確認し、「下書きをダウンロード」を押します。保存先を確かめた後、記事は `src/content/notes/`、作品は `src/content/works/` に、自分でダウンロードした `.md` を追加します。

ファイル名は半角の小文字・数字・ハイフンで、最大64文字です。先頭・末尾や連続するハイフン、拡張子、フォルダの指定は使いません。ブラウザが同名のダウンロードに番号を付けた場合も、そのまま既存ファイルに重ねず、別のファイル名をこの画面で指定して書き出してください。ファイルを移すときも、同じ名前の既存ファイルを上書きしないよう確認します。

タグは任意です。新しく書くタグはカンマか改行で区切り、空や重複を除きます。作品のURLやリポジトリは、掲載してよいHTTPSのURLがある場合だけ入力します。ログイン情報・空白・制御文字・バックスラッシュは含めません。表紙の設定は `images/` 配下のPNG・JPEG・WebP・GIF・AVIFと説明です。画像ファイル自体は、この道具へ取り込みません。

## Markdownを取り込む

本文の下の「Markdownを取り込む」を開き、ファイル選択欄で `.md` を1つ選びます。選んだファイルだけを画面内で読み、任意のパスやURLから読み込みません。容量は1 MiBまで、UTF-8で保存したMarkdownを使います。いまの入力がある場合は、同じ画面にファイル名と置き換え確認を表示します。「このファイルで置き換える」を押すまで題・本文・設定は変わりません。「取り込みをやめる」で入力を保てます。

先頭の `---` で囲んだ設定をYAMLとして読みます。記事は `category`、作品は `status`・`url`・`repository`・`cover` のいずれかで種類を判断します。両方がある場合や、どちらもない場合は止めます。題・要約・日付・タグ・公開設定と、記事の種類・作品の状態・URL・表紙の設定を扱います。知らない設定は名前を表示して取り込みを止め、黙って落としません。壊れたYAML、重複キー、独自タグ、エイリアス、文字列以外の題なども止めます。設定は64 KiBまでです。元ファイルには変更を加えません。

取り込んだ題と本文は書き直しません。本文を編集するまでは、改行・空白・強調記号・末尾の改行を含めて原文を保って書き出します。タグも編集するまでは元の配列を保ちます。YAMLの引用符や設定の並び方は書き出し形式にそろいます。取り込んだ種類は固定し、種類の切り替えで作品の表紙などが落ちることを防ぎます。旧ファイル名に日本語やアンダースコアがある場合も読めますが、ダウンロード前に安全な新しいファイル名へ変える必要があります。

元が `draft: false` のファイルも取り込めます。画面に元の設定を知らせ、書き出しは必ず `draft: true` に戻します。

## 読む表示と保存

「読む」は見出し・段落・強調・箇条書き・引用・コード・リンクの見え方を確認する簡易プレビューです。リンクは表示だけで、クリックやキーボード操作でも行き先を開きません。Markdownのすべての記法を再現するものではありません。本文の `#` 見出しはプレビュー内で `h2` 以下にして、画面の題と重ねません。元のMarkdownには変更を加えません。HTMLは文字として表示し、画像は代替テキストだけを表示するので外部画像を取得しません。`javascript:`・`data:`・`vbscript:` などのリンクは押せません。長い本文は10万文字または4,000行まで表示し、残りは編集欄で確認できます。「Markdownと設定を見る」では書き出す文字列全体を読めます。

入力は画面内だけで扱い、サーバー送信・自動保存・ブラウザ内への永続保存は行いません。画面を閉じたり再読み込みしたりすると入力を失うことがあるため、区切りでダウンロードしてください。最初の日付はUTCの当日です。記録したい日が違う場合は変更できます。

すべての書き出しは `draft: true` です。一覧と詳細ページには出ません。本人が内容と公開範囲を確認してから、Markdownの設定を `draft: false` に変えます。GitHubへの保存や外部公開は、この道具では行いません。

私的メール、非公開の業務資料、金融情報、内部メモ、認証情報は、入力・ダウンロード・リポジトリのいずれにも入れないでください。掲載を決めた画像は `public/images/` に置き、`src/data/public-assets.json` の配列へ `images/foo.webp` の形で追加します。本文では `![説明](/images/foo.webp)` と書き、外部画像URLは使いません。採用できる拡張子は小文字の `png`, `jpg`, `jpeg`, `webp`, `gif`, `avif` です。

`public/` へ未採用ファイルを置くとbuild前の確認で停止します。採用した画像は、記事のdraft設定に関係なく配布物へコピーされます。未採用画像は `public/` に置かないでください。画像ヘッダの形式確認は、画像全体のデコードやメタデータの除去ではありません。掲載可否と不要なメタデータは画像の用意時に確認します。具体的な手順は [CONTENT.md](CONTENT.md) にあります。

追加後は `npm run lint`、`npm run build`、`npm test` を実行します。サイトのbuildは本文のraw HTMLを拒否するため、HTMLのコード例はバッククォートやコードブロックで囲みます。HTMLコメントは生成ページから除去しますが、元のMarkdownは保持します。外部リンクはログイン情報・空白・制御文字・バックスラッシュを含まないHTTPSにし、本文ではサイト内のパスも使えます。簡易プレビューで読めたことを、サイトのbuild検証に置き換えないでください。

執筆画面自体を変更して確認する場合は `npm run build:local` と `LOCAL_STUDIO=1 npm test`、作品の比較版は `npm run build:compare` と `LOCAL_COMPARISON=1 npm test` を使います。通常の配布物を確認するときは両フラグを外して通常buildをやり直します。

GitHub Pagesのプロジェクト用baseを設定したプレビューでは、`http://127.0.0.1:4321/repo-name/write/` のようにbaseを付けます。起動・baseの設定方法は [README.md](../README.md) を参照してください。
