# 制作を、時間でたどる

作品を日付の手がかりから開き、その前後の公開記録へ移る非公開の比較案です。`maker-field-handoff` の `c0f2075df7cfb0e7fac2b78e1d0d947e9139d695` から、独立した `timeline-study` ブランチに作りました。既存7案とmainの採用状態は変えていません。

## 何を見返せるか

既に確認した公開GitHub 9リポジトリから、固定コミットを1件ずつ表示します。日付索引から一作品を選び、短い説明と日付の二欄を読み、前後の記録または根拠のGitHubコミットへ進めます。

PCは左の月別索引と右の一作品を並べます。細い弧は静止した装飾です。スマートフォンは索引を折り畳み、いま開いている作品を先に読みます。操作には通常のリンクとTab/Enterを使います。JavaScriptが無効な場合は全件を縦に表示します。

[ローカルで比較版を開く](http://127.0.0.1:4355/hamaya-site-draft/compare/timeline/)。同じ端末の確認サーバーが動いている間だけ使えるURLです。各ローカル画面の「時間で見返す（別タブ）」からも開けます。執筆中のタブはそのまま残ります。

| 欄                 | 根拠と扱い                                                       |
| ------------------ | ---------------------------------------------------------------- |
| 公開記録の日付     | 固定SHAの `commit.committer.date`。UTCで表示し、この日付で並べる |
| 制作日（本人入力） | 本人が入力した日付だけ。現在は全件「未入力」                     |
| 調査日             | 公開状態と説明を調べた2026-10-04。制作日として使わない           |

9件の追加照合では `commit.author.date` と `commit.committer.date` は同じ値でした。実際の制作開始・完成・作業時間・努力の量・公開開始日はここから推測していません。これは確認した各repoの1記録であり、本人の全制作履歴を表すものではありません。去年11月以降の私的な活動や経歴は補っていません。

同じUTC日にも各作品を残します。7月29日は3件、9月6日は2件あります。同日の並びはIDによる索引用の固定順で、制作の前後関係を示しません。前後リンクはこの表示順の隣へ進み、先頭と末尾では止まります。月や日の隙間を埋めたり、期間や件数を大きさ・濃さ・点数に置き換えたりはしません。

## 採用した場合の効果

「何を作ったか」の一覧に、「あの頃に残っていた公開記録」という戻り方が増えます。一作品を読み終えたところに前後の題と日付があるため、一覧へ戻らず隣の記録を開けます。分類を覚えていなくても、月の手がかりから選べます。

今回の並びは確認済みコミットの日付です。本人の制作日が揃えば、制作そのものを見返すための別の並びを検討できます。現在の画面では本人の制作日を追記しても公開記録の順序は変えません。主案への採用と、どの記録を掲載するかは本人の判断待ちです。

## データと配布の境界

説明・題・固定SHAは既存の [work-candidates.json](../src/data/work-candidates.json) を参照します。候補の `draft: true` と採否未定の状態は保持しています。追加照合の根拠は [date-sources.json](timeline-evidence/date-sources.json) に記録します。ソースコードや作品画像の転載、新しい外部依存はありません。

制作日は [creation-dates.json](../src/data/creation-dates.json) に作品IDと実在する `YYYY-MM-DD`、または `null` を記入します。現状は空のオブジェクトです。不明なID、不正な日付、丸めで成立する日付は拒否します。公開日付へ調査日を代入したり、不正入力を空状態として隠したりはしません。

ページは `LOCAL_TIMELINE=1` でだけ生成され、通常buildには画面・専用処理・入口が入りません。表示データはbuild時に確定し、閲覧中はGitHub API、外部画像、外部フォントを読み込みません。外部リンクは確認済みリポジトリと固定コミットだけです。前後移動ではURLのfragmentを使い、戻る・進むで選択を復元します。

担当者が再起動する場合は、この枝で `ASTRO_TELEMETRY_DISABLED=1 LOCAL_TIMELINE=1 BASE_PATH=/hamaya-site-draft npm run dev -- --port 4355` を実行できます。通常の閲覧操作でコマンド入力は不要です。

## 確認したこと

PC1280px・375px・320pxで、選択・キーボード・同日全件表示・先頭末尾の停止・横はみ出し・reduced motionを確認しました。固定fragmentへの直接移動、戻る・進む、不正fragment、JavaScript無効時の全9件も確認しています。

空のデータと本人入力日ありの表示は独立した検証用コピーで確認しました。実際の候補や本人の制作日ファイルは変更していません。検証に使った2024-02-29は合成の値として画面にも明示しています。

初版のPCでは選択中の索引が画面下へ流れていました。索引の内側だけをスクロールする形へ改め、ページ全体を動かさず選択行を表示します。日付の文字も12pxにしました。スクロールできることを短い補足で示し、索引の高さは画面の高さに合わせています。

最終版は1280×900・1280×768・375×812・320×640でも、ページを初期位置に保ったまま選択行を表示できました。Chrome 153の確認は12項目成功し、画面エラー・外部通信・通信失敗はありません。通常のmotion設定でも待機中のアニメーションはありません。外部GitHubリンクは正確なURLを検査し、作品コードやデモは実行していません。

最終lintは0エラー・0警告・0hint。通常root版、GitHub Pages用のbase付き通常版、timeline単独版、全ローカル比較併用版で各159テストが成功しました。通常版は5ページ、timeline単独は14ページ、全ローカル版は18ページです。
