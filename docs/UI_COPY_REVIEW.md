# UI文言の見直し案

`timeline-study`（`5ec128d`）から分けた `japanese-ui-copy` の比較案。本人の好みと採用判断は未確認です。既存案を保持し、公開・デプロイはしていません。

## 変更したところ

こちらで追加した案内文・ボタン・リンクを見直しました。押した後に起こることを具体的に書き、保存や採用と誤解されやすい言葉を避けています。

| 場所               | 変更前                                 | 変更後・意図                                                                                                                         |
| ------------------ | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 作品候補のチェック | 候補に残す                             | **候補を選ぶ**。タブ内の一時選択で、保存や掲載の決定ではないことを操作のそばに表示。                                                 |
| 下書きの確認       | 書き出しを確認                         | **下書きを確認**。確認だけでは保存されず、ダウンロードが別の操作であることを明記。                                                   |
| Makerの終了操作    | 読み込みをやめる                       | **記録を閉じて入力を消す**。入力が残る「開くのをやめる」と区別。                                                                     |
| 作品候補のカード   | 詳しい確認内容と未確認点を常時表示     | **コード・資料の詳細と、未確認の点**から開く。作品名・要約・選択・関連リンクを見渡しやすくする。未実行と本人確認待ちは主画面に残す。 |
| ページ間のリンク   | 作品を見にいく／GitHubでこの記録を開く | **作品の一覧へ／GitHubで変更内容を見る**。一覧と、特定コミットの変更内容を区別。                                                     |

自然な文は変更していません。本人の旧記事・自己紹介、作品名・説明・出典などのデータ、デザインの見出しは保持しています。

## 残した意味と条件

- 作品候補は未実行・掲載未定。担当範囲と制作期間は本人の確認待ちです。チェックは再読み込みで解除され、コピーするのはリポジトリ名・作品名・URLだけです。
- 入力は自動保存されません。書き出すファイルは常に `draft: true` で、画面から公開しません。確認とダウンロードを分け、ダウンロード開始を保存完了とは表示しません。
- Markdownの取り込みで入力を置き換えるときは確認します。取消では元の入力を保ち、元ファイルも変更しません。
- Makerでは、記録を選び直しても記録ごとの入力を保持します。別のJSONを開くか終了操作をすると入力を消去します。元JSONは変更せず、画像本体は下書きに含めません。
- 実験は「シドの試作（AI）」と表示し、本人の実績と区別します。コミット日時（UTC）と本人が入力する制作日も区別します。

## 検証

`npm run lint` は合格（Astro 100ファイル、エラー・警告・ヒント0）。通常ルート、GitHub Pages用の `/hamaya-site-draft`、全ローカル機能を含む同baseの3構成でbuildと159件のテストがそれぞれ合格しました。通常buildは5ページ、全ローカルbuildは18ページです。実験の帰属を確かめる既存テストは、新しい「本人の制作実績ではない」「掲載未定」の両方を検査するよう更新しています。

Chrome 153の実ブラウザでは27項目が合格しました。

- 候補のコピー内容がリポジトリ名・作品名・URLと一致。選択解除、再読み込みによる解除、選択0件の表示を確認。
- Writerの確認操作でダウンロードが発生しないこと、実際の書き出しが `draft: true` であること、取り込み取消で入力が残ることを確認。元が `draft: false` の取り込みも書き出し時は `true` に戻ります。
- Makerの取消・読み込み失敗で入力を保持し、別JSONと明示的な終了操作では消去。実際にダウンロードしたMarkdownを別タブのWriterへ取り込み、再ダウンロードした内容がバイト単位で一致。
- 実験2件の初期停止・再生・停止・再開・終了を確認。1280 / 375 / 320px、キーボードによる詳細の開閉、JavaScript無効時、reduced-motionでも確認。
- JavaScriptエラー、外部リクエスト、POST、ブラウザ保存領域への書き込み、合成元ファイルの変更は0。
