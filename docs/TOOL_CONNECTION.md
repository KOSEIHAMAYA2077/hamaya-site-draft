# 制作道具との小さな接続仕様

この文書は、制作道具の機能をこのサイトへ採用する際の受け渡し条件です。別スレッド `01a103c9-de53-732c-a273-fb3ec9c250dc` の実装は未読です。そこで作られている保存方式、ログの項目、画面の安全性が適合済みとは扱いません。採用前に実際の差分と出力ファイルを読み、この条件と照合します。

最初の採用単位は「制作道具が出したMarkdownを既存の執筆画面で読み、内容を確認して下書きとして持ち帰る」までです。ログの永続保存、画像の取り込み、自動関連付け、公開操作は別に検討します。機能の採用によって、本人の文章や公開判断を補いません。

## 受け渡すファイル

UTF-8の `.md` を1ファイルずつ渡します。`src/lib/draft-import.mjs` の `importDraft` と `src/lib/draft-export.mjs` の `exportDraft` を共通の入口にし、道具ごとに独自のYAML解釈を追加しません。現行の執筆画面は `src/local-pages/write.astro` です。

取り込みは利用者が選んだファイルだけです。ファイル全体は1 MiB、先頭のfrontmatterは64 KiBまで。任意のローカルパスやURLを受け取って読み込む入口は設けません。壊れたUTF-8、重複キー、未知キー、YAMLエイリアス、独自タグは入力を変更せず停止します。

| 対象           | 設定                                                                  |
| -------------- | --------------------------------------------------------------------- |
| 共通           | `title`, `description`, `date: YYYY-MM-DD`, `tags: string[]`, `draft` |
| 記事           | `category: 学び` または `雑記`                                        |
| 作品           | `status: 制作中`, `完成`, `記録` のいずれか                           |
| 作品の任意項目 | `url`, `repository`, `cover: { src, alt }`                            |

題・要約・本文・実在する日付は書き出しに必要です。作品のURLはログイン情報・空白・制御文字・バックスラッシュを含まないHTTPS、表紙は `images/` 配下の採用済みPNG・JPEG・WebP・GIF・AVIFと代替テキストを使います。記事と作品の設定を混在させません。新しいファイル名は64文字以内の半角小文字・数字・ハイフンで、既存のファイルを上書きしません。

取り込んだ本文とタグは編集されるまで原文を保ちます。YAMLの引用符や設定の並びは書き出し形式にそろいます。ログ固有の時刻や関連IDなど、現行にない項目は黙って落としません。必要なら項目ごとの変換規則とschema変更を別の採用単位にします。バージョン管理が必要でも、未対応の `schemaVersion` をfrontmatterへ追加したまま読み込ませません。

## 下書き、プレビュー、公開出力

すべての書き出しは `draft: true` にします。元が `draft: false` でもtrueへ戻します。ログ保存、Git保存、比較画面での作品選択を公開承認として扱いません。通常ページへの掲載は、本人が内容を確認し、明示的にfalseへ変更した後です。

この監査ブランチでは、`npm run build` の通常出力から `/write/`・`/directions/`・`/compare/` とそれら専用のbundleを外します。`npm run build:local` は `LOCAL_STUDIO=1` で執筆画面と方向性の試作を加え、`npm run build:compare` は `LOCAL_COMPARISON=1` で作品の比較版も加えます。現在の公開0件では通常5ページ、ローカル用12ページ、比較用14ページです。`npm run dev` は執筆画面と方向性の試作を含み、`/compare/` は `LOCAL_COMPARISON=1 npm run dev` の場合だけ表示します。

ローカル用・比較用の成果物を配布物へコピーしません。通常出力へ戻すときは両フラグを外してbuildし、不要ページとbundleが消えていることを確認します。これらのフラグ、ローカルホストでの入口表示、`noindex` はアクセス制限ではありません。

画面内の「読む」は `renderDraftPreview` に渡します。外部の道具が生成したHTMLを、そのまま `innerHTML` へ挿入しません。HTMLは文字、画像は代替テキスト、リンクは移動しない表示にする現行の境界を保ちます。プレビューで安全に表示できたことを公開本文の安全性の証明にしません。公開用Markdown、frontmatter、URL、画像は、**公開renderer側の監査済み検証を必ず通す**ことを接続条件にします。この文書自体は、その修復・検証の完了証明ではありません。

サイトのbuildでは本文のraw HTMLを拒否します。HTMLのコード例はコードとして記述し、HTMLコメントは生成ページから除去します。元のMarkdownは保存したままです。外部リンクは認証情報・空白・制御文字・バックスラッシュを含まないHTTPSに限定し、本文のサイト内パスは許可します。取り込んだ原文の保存と、配信HTMLへの採用を分けて検証します。

合成fixtureは検証用コピーであることを表示し、実際の本人データや配布物へ混ぜません。作品と記事の対応は `src/data/work-records.json` の明示的な設定だけを参照します。タイトルの類似や日付から関連を自動確定しません。読む導線は存在する公開済み記事に限ります。

## 画像と第三者素材

Markdownの受け渡しに画像ファイル自体は含めません。画像を採用するときは、掲載可能なファイル・出典・利用条件・代替テキストを別に確認します。追加画像は小文字拡張子 `png`, `jpg`, `jpeg`, `webp`, `gif`, `avif` のraster画像に限定し、`public/images/` に置きます。`src/data/public-assets.json` の配列に `images/foo.webp` の形で明示採用し、本文では `/images/foo.webp`、設定値では `images/foo.webp` を参照します。外部URL・相対ファイルimport・追加SVGは画像の受け渡し対象外です。

build前に任意の `public/` ファイル、未採用画像、シンボリックリンク、存在しない採用画像を拒否します。画像の拡張子とヘッダも照合しますが、完全な画像デコーダやメタデータ除去処理ではありません。画像全体の表示と不要なメタデータは別途確認します。`public/` 内の採用画像は記事のdraft設定に関係なくコピーされるため、未採用画像や非公開資料を置きません。

執筆用の配信コードにはentitiesとyaml、動的importにはViteのhelperが含まれます。対応する許諾文は `public/third-party-notices.txt` に同梱します。依存更新時は実際に配信されるコードと許諾文を見直し、`tests/third-party-notices.test.mjs` を通します。ビルド専用の依存がlockfileにあることと、ブラウザへ配布することを区別します。

## 保存と未保存入力

現行の題・本文・設定は画面内のメモリで扱い、自動送信や永続保存は行いません。画面の読み書き切替で入力を保ち、取り込み失敗・取り消し・古い非同期処理の完了で入力を置き換えません。置換はファイル名と影響を表示し、利用者の明示操作後に行います。表示中の本文や取り込みメタデータをlocalStorageやURLへ保存する機能は、この接続に含めません。

プレビュー中のリンクはクリックやEnterでも移動させません。表示モードの変更によるDOMの作り直しやページ遷移で、未ダウンロードの本文を失わない構造を保ちます。再読み込みや画面を閉じた後の復元は現行の保証に含まれません。新しい永続保存を採用する場合は、保存先・対象・消去・失敗時の挙動を別途定めます。

## URLとブラウザの境界

サイト内URLは `path()` と `BASE_URL` から作り、`/repo-name/` を直書きしません。rootとGitHub Pagesのプロジェクト用baseの両方で、静的アセットと執筆画面の動的importを確認します。公開originは `SITE_ORIGIN`、パスは `BASE_PATH` に分けます。

検索は既存の `note-query.mjs` を使い、URLへ残す条件を `q` と `category` に限定します。記事からの戻り先は既知の一覧に固定し、任意の `returnTo` を取り込みません。検索条件と比較画面の作品選択を、未保存の本文と同じ状態オブジェクトに混ぜません。

CSPを導入・変更する場合は、その時点の生成HTMLとJavaScriptに対して確認します。入力された本文を実行コードやイベント属性にしません。新機能を動かすために `unsafe-eval`、任意の外部origin、広い通信許可を追加しません。静的ページのinline script/styleを扱う必要がある場合は、buildが生成するhash等との整合性を検証し、執筆・ダウンロード・動き停止を実ブラウザで確認します。CSPだけを入力検証の代わりにしません。

## 最小の受入確認

1. 記事・作品の合成Markdownを往復し、本文、タグ、URL、表紙設定を維持する。書き出しは必ず `draft: true` にする。
2. 未対応キー、不正UTF-8、不正URL、YAMLエイリアス、容量超過で取り込みを止め、元の題・本文・設定と元ファイルを維持する。
3. 取り込み取消、ファイルの連続選択、遅れて完了した古い読み込み、プレビューのクリック・Enterで未保存入力を失わない。
4. 公開renderer側の監査済みfixtureで、raw HTML拒否、HTMLコメントの配布除外と元Markdown保持、URL・frontmatter・採用画像の境界を検証する。画像ヘッダ確認を完全デコードやメタデータ除去と扱わず、執筆プレビューの合格で代用しない。
5. rootとプロジェクト用baseで、記事と一覧の往復、検索条件、執筆画面の動的import、下書きダウンロードを確認する。
6. 通常buildへ下書き本文、合成fixture、執筆・方向性・比較画面、未採用画像やそれらの不要bundleが出ない。ローカル用フラグを外して再buildしたときも確認する。
7. 第三者許諾文が実際の依存バージョンと一致し、生成成果物へ全文同梱される。

採用時は該当機能のテストに加え、`npm run lint`、`npm run build`、`npm test` とbase付きbuildを実行します。これは公開操作を行う指示ではありません。

ローカル用の検証は `npm run build:local` の後に `LOCAL_STUDIO=1 npm test`、比較用は `npm run build:compare` の後に `LOCAL_COMPARISON=1 npm test` を使います。buildとtestでbaseとモードをそろえます。
